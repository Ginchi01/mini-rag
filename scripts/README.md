# 命令行版本（不依赖 FastAPI）

这两个脚本是最早的版本——直接在终端里跑，没有 HTTP 服务。

后来我把同样的逻辑重构成了 `app/` 下的分层结构，并用 FastAPI 暴露成接口。
保留这两个脚本是为了展示从「一次性 demo」到「可部署服务」的演进过程。

---

## 1. `ollama_chat.py` —— 多轮对话

验证 Ollama 本地模型的上下文能力。

```bash
python scripts/ollama_chat.py
```

```
你：你好，我叫芦靖琪
模型：你好芦靖琪……

你：我叫什么名字
模型：你叫芦靖琪。        ← 上下文生效
```

**实现要点**：模型本身是**无状态**的，上下文靠把历史 `messages` 数组整个传给 API。
历史太长会拖慢推理，所以加了截断（保留最近 20 条）。

## 2. `mini_rag.py` —— 最小 RAG（命令行版）

读文档 → 切分 → 向量化 → 余弦检索 → 拼 prompt → 生成。

```bash
python scripts/mini_rag.py
```

```
问题：骨龄和实际年龄差多少算异常
回答：骨龄与实际年龄的差值（BA-CA）超过 ±2 岁通常提示需要进一步检查。[2]

命中片段：
  [1] 0.548 | 骨龄与儿童生长发育.md | ## RUS-CHN 标准是什么 RUS-CHN 是中国儿童骨…
  [2] 0.372 | 骨龄与儿童生长发育.md | 且一致性差。深度学习方案大致分两类…
```

## 实测记录

### 三次迭代的召回分数

| 版本 | 改动 | top-1 分数 | top-1 内容 |
|---|---|---|---|
| v1 | 原始 | 0.535 | **文档的元信息**（“本文档是示例”）❌ |
| v2 | 清理知识库中的非知识性文本 | **0.548** | 真正的 RUS-CHN 定义 ✅ |
| v3 | 缩小 chunk（400→250 字） | 待测 | — |

**v1 的问题**：知识库里混入了“这是给 mini_rag.py 用的示例文档”这类元信息，
被检索到了还排在第一位，污染了上下文。

**结论：RAG 的上限由知识库质量决定，不只是检索算法。**

### 拒答能力

| 问题 | 结果 | 最高召回分 |
|---|---|---|
| 骨龄和实际年龄差多少算异常 | ✅ 答对 ±2 岁 | 0.548 |
| RUS-CHN 和 GP 图谱法有什么区别 | ✅ 答对计分法/图谱法 | 0.537 |
| **今天北京天气怎么样** | ✅ **“资料中没有提到”** | **0.343** |

**观察到的规律**：
- 能回答的问题，召回分数在 **0.55 以上**
- 不相关的问题，召回分数在 **0.35 以下**

**据此设计了 0.4 的分数阈值做拒答**——低于阈值直接返回“资料中没有提到”，
不调用 LLM。这样比只靠 prompt 约束更可靠，还省一次推理。

### 硬件实测（RTX 3050 Ti Laptop，4GB 显存）

| 模型 | Q4 大小 | `ollama ps` 显示 | 生成速度 |
|---|---|---|---|
| qwen2.5:7b | 4.7 GB | **55% CPU / 45% GPU** | 200 字约 **13 秒**（≈15 tok/s） |
| qwen2.5:3b | 2.0 GB | 100% GPU | 更快 |

**7B 的 Q4 权重 4.4GB，比可用显存（约 3GB）还大，必然溢出到 CPU。**
通过 `OLLAMA_FLASH_ATTENTION=1` 和 `OLLAMA_KV_CACHE_TYPE=q8_0` 压缩 KV cache 缓解。

## 与 `app/` 版本的区别

| | `scripts/` 命令行版 | `app/` 服务版 |
|---|---|---|
| 入口 | 终端交互 | HTTP 接口 `/ask` |
| 索引 | 每次启动重建 | 启动时构建一次（lifespan） |
| 结构 | 单文件 | 配置/切分/索引/生成分层 |
| 部署 | 无 | Docker |
| 测试 | 无 | pytest 覆盖切分逻辑 |
